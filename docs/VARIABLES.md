# Environment Variables

This document lists all environment variables required for local development of the EventPro platform.

## Backend (Spring Boot API)

The backend API service requires the following environment variables. These should be set in a `.env` file in the project root (used by Docker Compose) or as system environment variables.

<details>
<summary>Click to expand</summary>

### Database Configuration

```env
# Database connection URL
# Format: jdbc:postgresql://host:port/database
# For Docker Compose: use postgres:5432
# For local execution: use localhost:5432
DB_URL=jdbc:postgresql://postgres:5432/eventpro

# Database username
DB_USERNAME=eventpro

# Database password
DB_PASSWORD=eventpro
```

### AWS Configuration (LocalStack for Local Development)

```env
# LocalStack endpoint URL (for local development)
# When running in Docker Compose: http://localstack:4566
# When running locally: http://localhost:4566
AWS_ENDPOINT_URL=http://localstack:4566

# AWS Region
AWS_REGION=us-east-1

# AWS Credentials (for LocalStack, use test values)
AWS_ACCESS_KEY_ID=test
AWS_SECRET_ACCESS_KEY=test
```

### AWS Cognito Configuration (REQUIRED)

```env
# AWS Cognito User Pool ID - REQUIRED
# The application will fail to start if this is not configured
# Format: us-east-1_XXXXXXXXX
COGNITO_USER_POOL_ID=your-user-pool-id

# AWS Cognito App Client ID - REQUIRED
# The application will fail to start if this is not configured
COGNITO_CLIENT_ID=your-client-id
```

**Note**: Cognito credentials are required even for local development. LocalStack Community Edition has limited Cognito support, so you'll need to use a real AWS Cognito User Pool or LocalStack Pro.

### S3 Configuration

```env
# S3 bucket name for image storage
# Default: eventpro-images-local
S3_BUCKET_NAME=eventpro-images-local
```

### SQS Queue Configuration

```env
# Order processing queue URL
# Format: http://localhost:4566/000000000000/order-queue (LocalStack)
ORDER_QUEUE_URL=http://localhost:4566/000000000000/order-queue

# Payment processing queue URL
# Format: http://localhost:4566/000000000000/payment-queue (LocalStack)
PAYMENT_QUEUE_URL=http://localhost:4566/000000000000/payment-queue

# Notification queue URL
# Format: http://localhost:4566/000000000000/notification-queue (LocalStack)
NOTIFICATION_QUEUE_URL=http://localhost:4566/000000000000/notification-queue
```

**Note**: These queue URLs are typically generated by Terraform when running `make local-infra` and automatically added to the `.env` file.

### Stripe Configuration

```env
# Stripe Secret Key (for server-side operations)
# Use test keys for local development: sk_test_...
STRIPE_SECRET_KEY=sk_test_your_secret_key_here

# Stripe Publishable Key (for client-side operations)
# Use test keys for local development: pk_test_...
STRIPE_PUBLISHABLE_KEY=pk_test_your_publishable_key_here

# Stripe Webhook Secret (for webhook signature verification)
# Use test webhook secrets for local development: whsec_...
STRIPE_WEBHOOK_SECRET=whsec_your_webhook_secret_here
```

**Note**: For local development, you can use test keys. The application-local.yml provides default test values, but you should set real test keys for proper functionality.

### Optional: AWS Secrets Manager

```env
# Database secret ARN (optional - if using Secrets Manager instead of direct env vars)
DB_SECRET_ARN=arn:aws:secretsmanager:us-east-1:000000000000:secret:eventpro-db-secret

# Stripe secret ARN (optional - if using Secrets Manager instead of direct env vars)
STRIPE_SECRET_ARN=arn:aws:secretsmanager:us-east-1:000000000000:secret:eventpro-stripe-keys
```

### Spring Profile

```env
# Spring profile to use
# Options: local, dev, prod
# Default: local (when running via Docker Compose)
SPRING_PROFILES_ACTIVE=local
```

</details>

## Lambda Functions

Lambda functions run separately from the main backend service. They require their own environment variables when executed locally.

<summary>Click to expand</summary>

### Common Lambda Variables

All Lambda functions require these base variables:

```env
# Database Configuration
DB_URL=jdbc:postgresql://localhost:5432/eventpro
DB_USERNAME=eventpro
DB_PASSWORD=eventpro

# AWS Configuration
AWS_REGION=us-east-1
AWS_ENDPOINT_URL=http://localhost:4566  # For LocalStack
```

### Order Processor Lambda

```env
# SQS Payment Queue URL (where to send payment processing messages)
SQS_PAYMENT_QUEUE_URL=http://localhost:4566/000000000000/payment-queue
```

### Payment Processor Lambda

```env
# SQS Notification Queue URL (where to send notification messages)
SQS_NOTIFICATION_QUEUE_URL=http://localhost:4566/000000000000/notification-queue

# Stripe Secret Key (direct or via Secrets Manager ARN)
STRIPE_SECRET_KEY=sk_test_your_secret_key_here
# OR
STRIPE_SECRET_KEY_ARN=arn:aws:secretsmanager:us-east-1:000000000000:secret:eventpro-stripe-keys
```

### Notification Sender Lambda

```env
# SES Sender Email Address
# Default: noreply@eventpro.com
SES_SENDER_EMAIL=noreply@eventpro.com
```

</details>

## Frontend

The frontend React application requires the following environment variables. These should be set in a `frontend/.env.local` file (for local development) or as build-time environment variables.

<details>
<summary>Click to expand</summary>

### API Configuration

```env
# Backend API base URL
# For local development: http://localhost:8080
# For production: https://api.yourdomain.com
VITE_API_BASE_URL=http://localhost:8080
```

### Frontend AWS Cognito Configuration (REQUIRED)

```env
# AWS Cognito User Pool ID - REQUIRED
# Must match the backend COGNITO_USER_POOL_ID
# Format: us-east-1_XXXXXXXXX
VITE_COGNITO_USER_POOL_ID=your-user-pool-id

# AWS Cognito App Client ID - REQUIRED
# Must match the backend COGNITO_CLIENT_ID
VITE_COGNITO_CLIENT_ID=your-client-id

# AWS Region
# Default: us-east-1
VITE_AWS_REGION=us-east-1
```

### Frontend S3 Configuration

```env
# S3 bucket name for image storage
# Must match backend S3_BUCKET_NAME
VITE_S3_BUCKET_NAME=eventpro-images-local
```

### Stripe Configuration (REQUIRED for Payment Features)

```env
# Stripe Publishable Key - REQUIRED for payment processing
# Use test keys for local development: pk_test_...
# This is used client-side for Stripe.js integration
VITE_STRIPE_PUBLISHABLE_KEY=pk_test_your_publishable_key_here
```

**Note**: The frontend requires the Stripe publishable key to initialize Stripe.js for payment processing. This should match the `STRIPE_PUBLISHABLE_KEY` used in the backend.

</details>

## Environment File Setup

### Automatic Setup (Recommended)

The easiest way to set up environment variables is to use the Makefile command:

```bash
make local-infra
```

This command will:

1. Start LocalStack if not running
2. Provision Terraform resources (S3, SQS, Secrets Manager)
3. **Automatically create `.env` file** with all required backend values
4. **Automatically create `frontend/.env.local`** with all required frontend values

### Manual Setup

If you prefer to set up manually:

1. **Create `.env` file** in the project root:

   ```bash
   cp .env.example .env  # If example exists
   # Or create manually with the variables listed above
   ```

2. **Create `frontend/.env.local` file**:

   ```bash
   cd frontend
   cp .env.example .env.local  # If example exists
   # Or create manually with the frontend variables listed above
   ```

3. **Fill in the required values**, especially:

   - `COGNITO_USER_POOL_ID` and `COGNITO_CLIENT_ID` (must be from real AWS or LocalStack Pro)
   - `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, and `STRIPE_WEBHOOK_SECRET` (use test keys for local dev)

## Notes

1. **Cognito is Required**: Even for local development, you need real AWS Cognito credentials. LocalStack Community Edition has limited Cognito support. Consider using LocalStack Pro or a real AWS Cognito User Pool.

2. **Queue URLs**: These are typically generated automatically by Terraform when running `make local-infra`. They follow the LocalStack format: `http://localhost:4566/000000000000/queue-name`.

3. **Stripe Keys**: Use test keys (`sk_test_...`, `pk_test_...`) for local development. Never commit production keys to version control.

4. **Environment File Locations**:
   - Backend: `.env` in project root (used by Docker Compose)
   - Frontend: `frontend/.env.local` (used by Vite)

5. **Docker Compose**: When running via `docker-compose up`, environment variables from `.env` are automatically loaded and passed to containers.

6. **Lambda Functions**: Lambda functions have their own environment variable requirements and are typically configured via AWS Lambda console or Terraform when deployed.
